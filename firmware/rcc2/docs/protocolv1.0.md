# 具身智能巡检机器人 上下位机通信协议规范

*   **版本**：v1.0
*   **生效日期**：2026-XX-XX
*   **适用对象**：STM32F407（下位机 / 小脑） ↔ RK3588 / PC（上位机 / 大脑）
*   **修改约定**：任何字段变更或新增帧类型，必须双方同步升级版本号。

## 1. 物理层参数
*   **接口类型**：UART1（STM32） ↔ USB转TTL（上位机）
*   **波特率**：115200 bps（联调稳定后可升级至 460800 bps）
*   **数据格式**：8 位数据位，1 位停止位，无校验（8N1）
*   **字节序**：多字节数据（如 float、uint32）一律采用 **小端模式（Little-Endian）**，即低字节在前。

## 2. 数据帧结构定义
所有通信均以帧为单位，单帧最大长度为 39 字节（固定开销 7 字节 + 最大载荷 32 字节）。

| 字节偏移 | 字段名 | 长度(字节) | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | HEAD1 | 1 | 固定值 `0xAA` |
| 1 | HEAD2 | 1 | 固定值 `0x55` |
| 2 | TYPE | 1 | 帧类型（详见第 3 节） |
| 3 | LEN | 1 | DATA 字段的字节数 N（取值 0~32） |
| 4 ~ 4+N-1 | DATA | N | 有效载荷，多字节小端 |
| 4+N | CRC_H | 1 | CRC16 校验值的高字节 |
| 5+N | CRC_L | 1 | CRC16 校验值的低字节 |
| 6+N | TAIL | 1 | 固定值 `0x0D` |

## 3. 帧类型（TYPE）定义表
| TYPE | 方向 | 帧名称 | DATA 内容与长度 | LEN |
| :--- | :--- | :--- | :--- | :--- |
| `0x01` | 上位机 → 下位机 | 速度指令 | float v_left + float v_right | 8 |
| `0x02` | 下位机 → 上位机 | 里程计数据 | float x + float y + float theta | 12 |
| `0x03` | 下位机 → 上位机 | 电池电压 | float voltage | 4 |
| `0x04` | 下位机 → 上位机 | IMU 数据 | float ax, ay, az, gx, gy, gz | 24 |
| `0x05` | 上位机 → 下位机 | 心跳包 | 无（纯空载荷） | 0 |
| `0x06` | 下位机 → 上位机 | 心跳应答 | uint8 status (0=正常, 1=报警) | 1 |

## 4. 数据校验（CRC16）规范
*   **算法**：CRC-16/CCITT-FALSE（多项式 `0x1021`，初值 `0xFFFF`，无输入/输出反转）。
*   **计算范围**：仅计算 `TYPE` + `LEN` + `DATA`，**不包含**帧头 `0xAA 0x55`。
*   **传输字节序**：CRC 的计算结果按 **大端模式** 传输（高字节先发，低字节后发）。
*   **标准校验向量**：对 ASCII 字符串 `"123456789"` 计算，结果必须为 `0x29B1`。
*   **心跳校验向量**：对 `{0x05, 0x00}` 计算，结果必须为 `0xE2FA`。

## 5. 核心设计决策论证（面试/答辩得分点）

### 5.1 为什么双字节帧头 `0xAA 0x55`？
*   **防误同步**：单字节帧头在随机噪声中出现的概率是 1/256，极易造成“假同步”。双字节组合将概率降至 1/65536。
*   **波形友好**：`0xAA` (10101010) 与 `0x55` (01010101) 是位翻转互补的强交替模式，在逻辑分析仪上极易辨认，且与常见数据（如 ASCII、float 的 0x00/0x3F）重合率极低。
*   **分层防御**：即使极端噪声凑出了假帧头，后面的 CRC 校验和帧尾校验也会将其拦截并丢弃。

### 5.2 为什么要 LEN 字段？
*   **空间可变**：从心跳帧（LEN=0）到 IMU 帧（LEN=24），长度跨度大。若用固定长度会严重浪费带宽。
*   **向后兼容**：未来新增 `0x07` 参数下发帧（哪怕长度是 20 字节）时，解析器框架**无需修改**即可自动适配。
*   **防御性设计**：解析器要求 LEN ≤ 32，如果收到 `LEN=200` 则立即判定为失步噪声并丢弃，防止内存溢出。

### 5.3 为什么 CRC 计算范围不含帧头？
*   帧头的作用是“物理层同步定位”，并非业务数据。其正确性已经在解析状态机的 `WAIT_HEAD1/2` 阶段被严格检查过了。
*   若纳入帧头，接收方必须先缓存帧头才能开始校验，逻辑冗余且没有实际收益。业界标准做法均是 CRC 保护“帧头之后、CRC 之前”的字段。

### 5.4 心跳看门狗参数论证
*   **心跳周期**：100ms。在 115200bps 下，心跳帧（7字节）耗时仅 0.6ms，总线占用率 <1%，开销可忽略。
*   **超时阈值**：500ms（容忍连丢 5 个心跳）。Linux 上位机存在非实时调度抖动（如 USB 缓冲可达 16ms），该阈值能防止偶发延迟导致误刹停；同时，若真死机，500ms 内下位机强行停车，对于速度 <1m/s 的巡检车，滑行距离 <0.5m，处于安全范围内。
